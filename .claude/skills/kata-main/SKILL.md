# kata-main

設計の bad / good を **実際に動かして差分を見る** ためのエントリポイントを書く。

このリポジトリの目的は「読むだけだと腹落ちしない悪さを、エラーメッセージや
挙動の差分で見る」こと。よって main.php は動作確認スクリプトではなく、
**欠陥や不変条件を目に見えるようにする教材**として書く。

## 参照ファイル

観点カタログは bad / good で別ファイルに分けてある。
**対象が決まってから、対応する片方だけを読む。両方を先読みしない。**

| 対象 | 読むファイル | 中身 |
|---|---|---|
| bad | `references/bad.md` | 観点の選び方 / 観点カタログ / 例外の受け方 / bad のやらないこと |
| good | `references/good.md` | bad との1対1対応 / 観点カタログ / good のやらないこと |

章指定で bad と good の両方が対象になった場合も、
bad を書く時に `bad.md`、good を書く時に `good.md` と、都度片方ずつ読む。

## 前提となるディレクトリ規約

```
chapter-NN/
├── bad/
│   ├── ClassName.php   # 定義のみ。実行コードを混ぜない
│   └── main.php        # エントリポイント。小文字
└── good/
    ├── ClassName.php
    └── main.php
```

- 定義ファイルはクラス名と同じ大文字始まり、エントリポイントは小文字 `main.php`
- 読み込みは必ず `require_once __DIR__ . '/ClassName.php';`
  - `__DIR__` は末尾スラッシュを含まない。連結側の先頭に `/` が要る
  - `'./ClassName.php'` と書くと `bad./ClassName.php` になって落ちる
- 大文字小文字だけを変えるリネームは **削除 → 作成** の順で行う
  - macOS は大小を区別しないため、`git mv` なしだと追跡名と実ファイルがズレ、
    `core.ignorecase=true` により `git status` に永久に出てこない
- bad と good で同名クラスを定義しない。同一プロセスで両方 require すると
  `Cannot declare class/enum ..., because the name is already in use` で落ちる
  - 例: bad 側は `MoneyData` / `MoneyManager` のように、悪さが名前に出る形にする

## 引数

対象は引数で受け取る。受け付ける形は4つ。

| 渡されるもの | 例 | 対象 |
|---|---|---|
| 定義ファイルのパス | `chapter-04/bad/AttackPower.php` | そのファイルがあるディレクトリ |
| ディレクトリ | `chapter-04/bad` | そのディレクトリ |
| 章 | `chapter-04` / `04` / `4` | その章配下の `bad` と `good` 両方 |
| なし | — | 下のフォールバックで探索 |

- 章だけを渡された場合、`bad` と `good` の両方が対象になる。
  ただし定義ファイルが1つも無いディレクトリは飛ばす
- `04` や `4` のような数字だけの指定は `chapter-04` に解決する（ゼロ埋め2桁）
- 存在しないパスを渡されたら、勝手に近いものを推測せず、
  実在する章の一覧を出して確認する

### フォールバック（引数なし）

定義ファイルはあるが `main.php` が無いディレクトリを探す。

```bash
find chapter-* -mindepth 1 -maxdepth 1 -type d | sort | while read -r d; do
  [ -n "$(find "$d" -maxdepth 1 -name '*.php' -not -name 'main.php' -print -quit)" ] || continue
  [ -f "$d/main.php" ] || echo "$d"
done
```

- `main.php` 以外の `.php` が1つも無いディレクトリは候補にしない
  （空の `good/` を作った直後に誤爆させないため）
- zsh では `chapter-*/*/` の glob が空ディレクトリで
  `no matches found` を出すので、上記の `find` 版を使う
- 結果の扱い:
  - **0件** — 「全て作成済み」と伝えて終わる。何も作らない
  - **1件** — そのまま対象にする
  - **複数** — 一覧を出して、どれを作るか確認する。黙って全部作らない

## 手順

1. 上の規則で対象ディレクトリを確定し、定義ファイルを読んで
   bad / good どちらかを判定する
2. **本の該当節が「何を悪い」と言っているのかを1文で確定させる**
   - この1文が、観点を選ぶ唯一の基準になる。曖昧なまま先に進まない
   - 定義ファイルから読み取れなければ推測せず、どの節の話かを確認する
   - 例(chapter-05 MagicPoint): 「引数が多いと、値を揃える責務が呼び出し側に残り、
     同じ組み立てが呼び出し箇所の数だけ複製される」
3. 対象に対応する参照ファイルを読む（bad → `references/bad.md` /
   good → `references/good.md`）
4. 参照ファイルの「観点の選び方」に従って観点を確定させる
5. 下の出力規約に従って main.php を書く
6. `php -l` と実行で確認する
7. 実行結果を報告する。**期待通りのエラーが出ているかまで見る**

## 出力規約

- **`printf` で桁を揃える**。`%3d` などで数値を縦に並べ、変化を目で追えるようにする
- **前後を必ず並べる**。「初期状態」の行がないと何が変わったか分からない
- **因果を先に置く**。`$a === $b` の判定のように、事故の原因になる事実を
  結果より先に出力する
- **ラベルは日本語**。全角の幅を揃えて左端を合わせる
- **矢印コメントで注目点を示す** — `<- B には何もしていない`
- `var_dump` は構造を見せたいとき（good の完全性の証明など）に使い、
  値の変化を追うときは `printf` を使い分ける

出力例:

```
同一インスタンスか : yes
初期状態           : A =  50 / B =  50
A を +50 強化      : A = 100 / B = 100  <- B には何もしていない
```
