# kata-main — bad 側

`bad/` の main.php を書くときに読む。good を書くときは `good.md` を読む。

## 観点の選び方

**SKILL.md 手順2 で確定させた「この節が何を悪いと言っているか」の1文に紐づくものだけを選ぶ。**
クラスの性質に当てはまる、という理由だけで拾わない。

- **カタログは拾うためではなく、絞るためのリスト**。
  クラスの性質に当てはまるものを順に拾うと必ず盛りすぎる
- コードを読めば他にも欠陥は見つかる。1文に紐づかないものは書かない。
  たいてい別の章の主張(プリミティブ型執着・不変性など)であって、
  ここで混ぜると章の焦点が消える
- **件数を先に決めない**。1文から導けるものが2件なら2件で終わる

## 確認観点カタログ

### 生成の不完全さ
- **未初期化のまま使う** — typed property は初期値なしだと
  `Error: Typed property X::$y must not be accessed before initialization`。
  `new` は成功するのに使う時まで壊れていることが分からない、が肝
- **不完全なまま正常っぽい答えが返る** — 一部のプロパティだけ埋めて操作すると、
  未設定の項目を無視した「もっともらしい値」が返る。
  **落ちるより怖い**ので、落ちるケースより優先して見せる価値がある

### 生成後の破壊
- **public プロパティでバリデーション迂回** — `$obj->value = -999;`
  コンストラクタが保証したはずの不変条件を生成後に壊せる
- **参照共有による波及** — PHP のオブジェクトは代入で参照が渡る。
  `$b = $a;` して `$a->mutate()` すると `$b` も変わる。
  可変クラスの事故として最も分かりやすい。`$a === $b` を先に出すと因果が読める

### 型の緩さ
- **暗黙の型変換** — `declare(strict_types=1)` が無いと `int` 宣言に
  `"100"` も `true` も無言で通る。`1.5` だけは Deprecated が出る。
  **警告が出ない string / bool の方が危険**という順序で見せる
- **不正な文字列が素通り** — 通貨や区分を `string` で持つと `"US"` のような
  タイポが生成時に通り、バグが後段まで遅延する
- **意味を成さない操作が通る** — 金額 × 金額のように単位が壊れる計算。
  シグネチャ自体が間違っていても型が許してしまう
- **戻り値で型情報が失われる** — `add(): int` のように生の型で返すと、
  以降その値は何の単位かを失う

### 責務の分離
- **データクラス + 操作クラス** — 状態を持つだけのクラスと、それを操作する
  マネージャに分けると、不変条件をどこも守らなくなる

## 例外の受け方

後続の検証に到達させたいときは try/catch で受ける。捕まえる型を間違えると
そのまま Fatal error になるので注意する。

| 事象 | 投げられる型 |
|---|---|
| 未初期化プロパティへのアクセス | `Error` |
| 型宣言に合わない引数 | `TypeError` |
| enum の `from()` に不正な値 | `ValueError` |
| 自前のバリデーション | `InvalidArgumentException` |

`TypeError` / `ValueError` は `Exception` ではなく `Error` 系なので、
`catch (Exception $e)` では捕まらない。まとめて受けるなら `catch (Throwable $e)`。

**1ケースだけ見せて終わるなら catch しない**方がいい。Fatal error のスタックトレースが
「どこで壊れたか」を語ってくれるので、教材としてはそのまま出す価値がある。

## やらないこと

- 観点を全部盛りにしない。章の主張に関係ない欠陥まで並べると焦点が消える
- **観点を削った後、空いた枠を埋めない**。「2つだと少ないから何か足そう」は
  必ず主題の外から観点を持ってくることになる。枠は空いたままでいい
- 警告や静的解析エラーを消しにいかない。**怒られること自体が bad の証明**。
  消したくなったら、コメントで「この警告が出るのが主旨」と明記する

## 実行結果の見方

bad は「落ちるのが正しい」ケースがある。**エラー = 失敗ではない**。
